kugiri (区切り)

Splits text into lines, words and characters exactly where the browser already broke it.

kugiri (区切り) is the point where one segment ends and the next begins. That is what this library finds: the line boxes the browser painted, the words and graphemes inside them, and nothing else. It cuts the DOM at those points and marks every unit so you can animate it, in CSS or in script. It never decides where a line should break; the browser did that already.

Every case below is one piece of text in a situation running text can be in: a drop cap, a link that wraps, a float, a second script. Each one splits and reveals as it scrolls into view.

One ES module, about 7.0 kB minified and gzipped, with no dependencies.

kugiri (区切り) is a split engine and nothing more. It writes the units and stops: no animation, no watching the viewport, the fonts or the text. Both belong to the code that calls it, in whatever library it likes. The snippets below are not part of the library and do not ship with it. They are this page's own code, shown as one way to do each, in plain browser APIs and in plain CSS.

The reveal, an example. Each unit rises out of its mask with the Web Animations API, staggered by its index. GSAP or Motion would take the same elements. 

// Not part of kugiri: this page's own reveal, one way to animate the units.
const split = splitText(target, { type: ["words"], mask: "words" });

const reveal = split.words.map((word, index) =>
  word.animate(
    [
      { transform: "translateY(100%)", opacity: 0 },
      { transform: "none", opacity: 1 },
    ],
    {
      duration: 1000,
      delay: index * 30,
      easing: "cubic-bezier(0.23, 1, 0.32, 1)",
      fill: "backwards", // hidden until its turn, at rest when done
    }
  )
);

// A mask clips at rest too (descenders, focus rings), so the clip goes once the reveal is over.
await Promise.all(reveal.map((animation) => animation.finished));

for (const mask of split.masks) {
  mask.style.clipPath = "none";
}

The same reveal in CSS only. The split writes every unit's index as a custom property, so a stylesheet can stagger off it and no script has to animate anything. The CSS-only reveal case runs this way: the page splits it into words, sets one attribute, and the stylesheet does the rest. 

/* Not part of kugiri: this page's own CSS-only reveal, one way to animate the units. */
.css-reveal [data-word] {
  opacity: 0;
  transform: translateY(0.6em);
}

.css-reveal[data-revealed] [data-word] {
  animation: rise 0.8s cubic-bezier(0.23, 1, 0.32, 1) forwards;
  animation-delay: calc(var(--word) * 30ms);
}

@keyframes rise {
  to {
    opacity: 1;
    transform: none;
  }
}
// The only script the CSS-only reveal needs.
splitText(target, { type: ["words"] });
target.dataset.revealed = "";

The next layout, an example. A split is a snapshot of the layout the text had when it ran, and nothing splits again on its own. This page watches the width of the column the cases sit in and, when it changes, reverts every split and splits again, with no reveal a second time: the text stays responsive and the units sit at rest. 

// Not part of kugiri: this page's own resize handling, one way to do it.
let width = main.clientWidth;
let timer = 0;

new ResizeObserver(() => {
  if (main.clientWidth === width) {
    return; // a taller viewport moves no wrap
  }

  width = main.clientWidth;
  clearTimeout(timer);
  timer = setTimeout(resplit, 150); // once a drag settles
}).observe(main);
